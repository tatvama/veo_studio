# Tatvam v3: what was built and how it fits together

*Companion to `TATVAM_PLAN.md`. This describes the code as of 9 October 2026.*

## 1. Characters stay the same person

| Piece | Where | What it does |
| --- | --- | --- |
| Reference pack | `workers/handlers.py` (`character_sheet`, `character_outfit`, `character_lighting`) | Turnaround now includes the **back** view; every outfit gets a **3-angle mini turnaround** (front, three-quarter, full body) with `CharacterAsset.view`; **lighting variants** (day, dusk, night interior) with `CharacterAsset.lighting`. |
| Character Lock | `core/lock.py`, `Character.lock` | Structured constraints (face, body, skin & hair, voice, costume continuity, gestures, age, lighting, strictness). `prompt_text()` is appended to every prompt; `strictness` shifts the face-match and vision QC thresholds and decides 1 or 2 references per character; `costume_continuity` makes QC fail a wrong outfit. |
| Versions | `CharacterVersion`, `pipeline/prompting.look_of()` | A frozen look (DNA, voice, lock, approved asset ids, trained identity) for an inclusive episode range. Prompts, references and QC for episode N use the version that covers N. `POST /character-versions/{id}/restore` rolls the character back. |
| Costumes | `Costume`, `prompting.outfit_for()` | Named outfits with a description and episode range. A shot wears its own pick, else the scene wardrobe, else the default costume. The outfit's turnaround images are the first references. |
| Props | `Prop`, `ProjectProp`, `Scene.prop_ids`, `Shot.prop_ids` | Reusable objects with an optional reference image; named in prompts and passed as keyframe references. |
| Pronunciation | `Project.pronunciations`, `Character.name_pronunciation`, `pipeline/voice.say()` | Applied to every line before TTS (whole words, longest term first). The name pronunciation also goes into Veo prompts. |
| Trained identity | `identity`, `_loras_for()` in handlers | LoRA still sharpens keyframes; it now also rides along to catalog engines that expose a `loras` input (`GenRequest.loras`). |

## 2. The Google dialogue route

`pipeline/prompting.compile_video_prompt()` writes the prompt in the order Veo keeps best:

```
[SHOT] ...                      the action first
[DIALOGUE] Ravi (pronounced RAH-vee; voice: warm medium-low, calm) says in Kannada, quietly: "..."
[CHARACTERS] DNA + outfit + lock sentence
[LOCATION] ... [CONTINUITY] ... [STYLE] ... [AUDIO] ... [AVOID] subtitles, on-screen text, ...
```

- `native_dialogue_languages` (team setting, project override in `brief.native_languages`) lists the languages Veo may speak itself. `effective_voice_mode()` returns `native` for them when the dialogue method is `native` / `native_when_possible` (or for a one-language short or ad).
- **Dubbing**: with `dub_method = regenerate` and a native language, the `dub` orchestrator queues `video` jobs with `{language, native: true}`; the result is saved as that language's **lip-sync take** (`params.method = "native"`), so the timeline and export use it exactly like a re-synced clip. Other languages keep the TTS + sync.so route.
- **QC** (`qc` handler): besides face match and vision checks, a spoken take is sent to Gemini with the expected line (`dialogue_check`): words heard, language, word match, pronunciation, lip-sync, burned-in text. `dialogue_words_threshold` decides; a failed native take is regenerated, a failed re-dub gets the next lip-sync engine.
- `dialogue_warnings()` flags lines too long for the clip (10/16/22 words for 4/6/8 s) and two speakers in one clip; `GET /shots/{id}/prompt` and `GET /shots/{id}/dialogue-check` return them.

## 3. Script first

- **@mentions** (`core/mentions.py`): `@[Ravi](character:12)` tokens in script text and line speakers. `plain()` strips them for prompts and the breakdown; `resolve()` turns bare `@Name` into tokens (creating cast members when asked); `attach_entities()` links mentioned characters, locations and props to the project. `GET /projects/{id}/mentions?q=` feeds the editor; `POST /mentions/create` quick-creates; `POST /episodes/{id}/script/resolve`.
- **Import wizard**: `POST /episodes/{id}/import/apply` maps or creates every speaker, saves the board and writes the Story script with tokens.
- **Script intelligence** (`core/dependencies.apply_script_changes`): a changed dialogue line updates the shot that speaks it and flags its voice, lip-sync and spoken-video takes. `PATCH /episodes/{id}` returns `script_changes`.

## 4. Change impact

`core/dependencies.py` keeps the graph: framing/camera/action/cast/outfits/location/props/references → keyframe → video → lip-sync; dialogue[lang] → voice[lang] → lip-sync[lang] and spoken videos; narration[lang] → narration[lang]. `PATCH /shots/{id}` and the board save call `mark_stale()`; new takes clear the flag for their kind (`clear()`); a stale keyframe is remade by the next video job. `GET /episodes/{id}/impact` lists everything stale with the cost to redo; `POST .../impact/regenerate` queues it; `POST /takes/{id}/fresh` accepts a stale take as is.

## 5. Film Map links

`Shot.continuity_from_shot_id` + `continuity_mode` (`last_frame` | `extend`). The keyframe handler starts from the linked shot's last frame; with `extend`, the video handler generates this shot as an extension of the linked clip (parent take set). `POST /shots/{id}/next` (and the Director's `next_shot`) creates the following shot with the same cast, wardrobe, location and props, already linked.

## 6. Continuity Bible and wardrobe

`core/continuity.py`: `end_state()` asks the AI for the state at the END of a scene (outfit and physical state per character, props, time of day, weather, notes) from the script, the scene card and the previous scene's state; it is stored on `Scene.end_state` and carried into the next scene's prompts (`[CONTINUITY] carried over from the previous scene: ...`). `wardrobe_timeline()` lists who wears what per scene and flags changes the script did not ask for.

## 7. Production control

`core/dashboard.py`: per episode and per project: shots by status, planned/approved/generated seconds, rejected takes, regeneration rate, stale takes, spend by provider, wasted spend, **cost per approved second**, estimated remaining spend, queue and approvals. `Season` rows group episodes (`/projects/{id}/seasons`).

## 8. Gateway flags and the Director

Every engine's capabilities now carry `speech_in_video`, `audio_driven`, `lora_input`, `lipsync_to_audio` (derived from the model's input schema; built-ins set by hand). `engine_language_scores` (team setting) holds the Phase 0 listening results per engine and language.

The Director gained tool groups for v3: `continuity_state`, `wardrobe_report`, `impact_report`, `regenerate_stale`, `next_shot`, `lock_character`, `freeze_look`, `add_costume`, `set_dialogue_route`.

## 9. Tests

`backend/tests/test_v3.py` (8 end-to-end tests in mock mode), `test_v3_director.py`, `test_storage.py`; the whole backend suite runs with `backend\.venv\Scripts\python -m pytest`.
